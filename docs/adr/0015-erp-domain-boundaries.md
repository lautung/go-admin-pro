# ERP v1 域边界：主数据独立、业务流零打通

**Status**: accepted

ERP 引入与 CRM 重名且相邻的概念：两套产品（CRM 产品被商机/合同引用，ERP 产品被采购/销售单据引用）、两套客户（CRM 客户管过程与归属，ERP 客户是销售单据的往来单位）。决定完全对标芋道：主数据独立建表（`erp_product` / `erp_customer` / `erp_supplier`），互不同步；业务流 v1 零打通——CRM 合同不生成 ERP 销售订单，ERP 收款单不冲抵 CRM 回款记录，报表不跨域。术语在 GLOSSARY 划界：合同是法务约定，销售订单是履约单据；回款记录是 CRM 合同维度的收款事实，收款单是 ERP 结算维度的资金单据。

对芋道的一处主动收紧：客户/供应商被任何单据引用时禁止删除（芋道直接删、无引用校验），对齐项目自 CRM 以来的删除约束惯例；差异记入 ERP spec 的「与芋道差异」清单。

原因：共享主数据或业务打通需要双向同步与一致性机制，单人串行项目的首个 ERP 里程碑无法收口；独立建模与芋道零差异，参照物即现成答案。代价：跨域集成（合同转销售订单、客户主数据归一）后续需单独立项；同一租户会在两套客户/产品间重复建档，当前接受。
