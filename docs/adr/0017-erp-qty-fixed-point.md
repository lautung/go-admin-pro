# ERP 数量：毫单位定点类型

**Status**: accepted

ERP 库存账需要对小数数量做累加（芋道 `decimal(24,6)`，文档口径 3 位小数，如 0.5 千克），而金额已用「分定点 int64」的 Money 值类型；数量若用 float64 会在余额与流水重放中累积精度误差。决定数量与 Money 同构：Go 侧毫单位（10⁻³）int64 定点值类型（`internal/pkg/qty`，解析/范围校验/运算模式参照 money 包），落库 `decimal(24,3)`；明细金额 = 单价(Money) × 数量(qty)，128 位中间量防溢出。CRM 行项目维持 `int` 正整数不迁移（CRM 无库存概念，两域零打通）。

代价：新增一个值类型及其测试面；ERP 全部单据明细数量用它，改类型成本高。收益：库存账全程定点、余额恒等于流水代数和可精确重放，与 Money 的精度纪律一致。
