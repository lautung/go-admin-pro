# ERP 库存：纯数量账 + 反审核反向流水

**Status**: accepted

芋道 ERP 的库存只有数量（仓库×产品余额 + 流水），没有成本核算与库存金额；单据支持反审核，通过成对定义的反向流水（原流水不删）回滚，并以「下游收付款/后续单据存在则禁止」约束。ERP v1 完全对标：审核落账（未审核不动库存）、负库存禁止（应用层与 SQL 双保险）、反审核允许且走新增反向流水、已审核单据不可修改不可删除。

明确拒绝的增强：移动加权平均成本（余额带金额、出库转成本、毛利可见）。成本会被后续出库持续改写，反审核回滚在数学上不可靠——上成本核算就必须禁反审核、重写更正路径，复杂度与测试面显著上升，超出单人首个里程碑的收口能力。

代价：系统无库存金额与毛利口径，报表只有数量与单据金额；成本核算列 backlog，届时需翻转本 ADR 的反审核策略并单独立项。
